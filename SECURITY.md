# Security Policy

## Supported Versions

We actively issue security patches and updates for the following supported versions of **RetailSale / FAMALTH LYNX**:

| Version | Supported |
| ------- | ------------------ |
| `1.0.x` | :white_check_mark: |
| `< 1.0` | :x: |

---

## 🔒 Reporting a Vulnerability

Because **RetailSale** handles critical enterprise operations—including point-of-sale transactions, customer data, employee payroll, and financial ledgers—we take security vulnerabilities very seriously.

> [!IMPORTANT]
> **Please DO NOT report security vulnerabilities through public GitHub issues.**

### How to Report Security Issues

If you discover a security vulnerability, please disclose it responsibly by sending an email to:

📧 **help@famalth.com**

Please include as much of the following information as possible to help us understand and resolve the issue quickly:

1. **Type of Issue**: (e.g., SQL Injection, Authentication Bypass, XSS, Remote Code Execution, Privilege Escalation).
2. **Component Affected**: (e.g., Node.js API endpoint, PostgreSQL database query, JWT verification, Flutter client storage).
3. **Steps to Reproduce**: Detailed steps, proof-of-concept payload, or script demonstrating the vulnerability.
4. **Impact**: Potential consequences if exploited by a malicious actor.

### Our Security Response Process

1. **Acknowledgement**: We will acknowledge receipt of your vulnerability report within **48 hours**.
2. **Investigation**: Our maintainers will verify the vulnerability and assess its severity.
3. **Patching**: We will work on a fix and prepare a security patch release.
4. **Public Disclosure**: Once the patch is deployed and verified, we will publicly acknowledge your responsible disclosure (unless you prefer to remain anonymous).

Thank you for helping keep RetailSale and our user community secure!
